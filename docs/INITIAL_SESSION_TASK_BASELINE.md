# 初始会话原生任务与修复记录

首轮准备包仅含脚本、CI和验收合同，当时尚未执行原生浏览器。现已在5cce得到下文记录的原生红基线，后续核心候选仍须新SHA独立验收。应用代码基线为 `6290160`；脚本依赖 `e90ed2b37fb8c2393681f3062fe368d88172b210` 正式加入的稳定弹窗目标观察函数，因此最早可运行的仓库基线是 **e90**。首轮测试提交不包含 App/authStore/apiClient 初始就绪修复，也不修改 Login、Splash、品牌资源或应用的 12 秒初始化截止。

## 两条独立链路，各自 1280/360

一个 `initial-session` CI matrix 分片，通过现有 `isolated` 模式顺序创建四个全新浏览器 profile。每次先完整关闭该 profile 再进入下一个；不复用会话、cookie、账号或本机记录。四个合成手机号为 `13900008601` 至 `13900008604`，与已有脚本范围分开。

1. **初次401**：全新 profile 直接请求 `/todo?view=all`，观察应用自身实际 GET `/auth/me` 的 HTTP401；必须进入真正可读的 Login。用正常验证码按钮、合成后端 devOTP、验证和注册控件创建账号，直接返回完整的 `/todo?view=all`，读取待办页标题并用 GET 确认身份及只读 IDB 确认账号库。Todo 路由不包根首页的 FirstVisitGate，不能凭首页引导代码推断此链会丢失目的地。
2. **主动退出后重入**：另一全新 profile 从公开 `/login` 开始，用真实控件注册、完成引导、发现 Todo 入口并创建一条「Synthetic 保留{宽度}」待办。明确选无日期，核对 medium/未完成/null完成事实；保存完整本机行、原始服务端变更事件、同ID版本回执、空的整个outbox。通过真实设置入口点击「退出登录」，读到 Login 且私有待办/应用导航不出现；GET-only探针另证当前浏览器收到401（本任务不重放旧凭据）。保留账号库身份、版本、schema、完整 Todo/outbox 和 Todo 同步回执完全一致。随后直接重入 `/todo?view=all`，仍需见到 Login 和私有内容缺席；用相同账号原生 OTP 登录，返回完整路径、相同账号和原待办编号，原本机行/完整服务端ledger/回执/outbox无变化。

这两个分支单独 catch、单独首失败、单独媒体。第一条预期出现的 spinner 不能令第二条退出分支被跳过。第三/四条窄屏也独立执行。

## 原生操作与观察边界

- 仅声明的初始 `/login`、初始 protected URL 和退出后 protected URL 使用直接导航；业务过程使用真实可见入口、原生鼠标/键盘/滚轮。没有 DOM click、滚动注入、store调用、auth/cookie/state注入、业务写API或IDB写入
- 读取控件要求实际画面已绘制、完整落在视口及所有裁剪祖先内、完整文字宽度可读、中心点击命中。手机底栏与滚动容器沿用现有Y6L规则。原生悬停后观察同一目标三个连续稳定帧，最终重新核验，再单击一次；不会重放不确定的点击
- OTP来自这个CI创建的隔离后端原生send-code响应；不保存OTP到动作日志，不使用付费/真实SMS或模型服务
- 服务端证据仅当前页同源credential的GET `/auth/me` 与完整分页 `/sync/pull`，无手工设置cookie或Authorization。应用初次401与后续只读探针明确分别标记
- IDB先枚举已有库，再以无版本参数打开，升级事件立即中止；所有表仅readonly。记录原始行以及带类型的完整表示，保留undefined、负零和未知嵌套字段，不制造缺失库。不以账号库仍在的布尔值代替原记录/outbox比较
- 不将本机创建行缺少服务端创建/更新时间误判为业务字段丢失；业务字段逐项严格比对，任何额外本机字段也须与真实服务端对应。完整原本机行和完整原服务端事件分别跨退出/重登录严格比较，不删除源字段来获得通过

## 截止、首失败与工件

每个场景有85秒外层取证截止，路径/Login等待18秒，GET/IDB各5秒，稳定目标2.5秒。它们只约束测试，不改变应用12秒初始化期限、不自动重试登录/退出/保存、不在首失败后继续业务点击。超时/首失败立即禁止后续控件操作，保留首失败轨迹、截图与可读原账号快照，然后由已有隔离器关闭录像、trace及profile。媒体结束错误也必须先成功关闭profile才能开始下一场；无法确认关闭则停止并报基础设施错误。

继续使用 `audit-user-outcomes.mjs` 的PNG/画面状态、12fps webm、Chromium trace与阶段checkpoint。新增 `initial-session/<场景>/first-failure.json`、`initialization-chronology.json`、完整账号/ledger前后快照、`scenario-result.json`；根目录 `YI-media.json` 逐场记账。首失败不被后来的结束截图覆盖。

安全初始化collector逐字复用 `e2e-recovery.mjs` 的已测试白名单实现，并有纯测试检查字节一致。每场独立最多2048条，仅固定阶段、安全异常名称、布尔值和计数；账号编号/内容/cookie/头/查询参数/原异常文本不进入新初始化轨迹。原始合成业务数据仅在明确标记的账户取证文件及既有媒体中。

现有 always() 递归归档/分块/哈希清单会保留新增子目录及失败媒体，本包不改归档器或放宽缺少媒体检查。webm/trace有字节不是播放/内容有效的结论；须后续独立实图、录像、完整trace审核。CI结果仍非零表示失败，expected RED不转为PASS或continue-on-error。

## 初始就绪修复候选

App只在身份已检查且已认证时加载账号资料；确认签出的保护页可立即进入原有登录跳转并保存目的路径。API的401/账号不符409携带它自己撤销得到的会话代次，authStore只接受仍属当前请求、当前页面会话的精确回执，避免把自己的撤销误判成另一场登录；真正迟到的响应仍不能撤销新账号或同账号的新会话。签出库绑定跨await仍检查权限，存储失败保持可见的身份不可用状态，不假装成功。

候选只有App、apiClient、authStore三份业务源码和对应回归测试；actor、数据库绑定、同步引擎、useAppInit的12秒截止及现有初始/恢复读竞态均未改。Login、Splash和品牌文件字节不改。原生脚本保留全部动作、截止、源对象及结果断言，只把退出证据说明收窄到当前浏览器401，措辞修正不算行为修复。

原模块15场景在b666为10通过/5失败，同一套在候选15通过；另有独立73个对抗场景、74个App/路由检查和完整候选前端545项通过。合入当前5cce测试树后，本地前端567项、后端55项及双端lint/类型/构建通过。它们含fake-indexeddb、合成传输和确定性React/router测试替身，不替代下一精确SHA的原生新注册/退出重入/回原路径与完整记录验收。既有初始/恢复加载竞态及旧b5b8根因仍开放。

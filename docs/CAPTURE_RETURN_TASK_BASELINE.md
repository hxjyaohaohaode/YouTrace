## A 的返回连续性，与当前稿诊断严格分开

1. 每次打开或输入之前冻结完整源。A 校对完毕，等待可见“确认稿已保留在本机”，保存 A 的确切 ID、完整字段与元数据、原 inputKey/raw/context、实际修正和当前入口。
2. 点击确认页真正的顶部“返回”，再读取 composer 的完整原文和可见继续控件，随后点击真正“查看确认稿”。不使用手写 draft URL、session 指针或浏览器历史调用代替这个操作。
3. 返回前后逐值保留 A 和其原输入。当前源码的 composer 会再创建输入副本，主按钮会建立新确认 ID B，并按原文重新解析。若原生确实观察到 B／原修正没有随主入口继续，记录主入口修正连续性 RED，不能称为 A 已删除，也不能因 A 仍在存储而把用户链授绿。
4. composer 顶部“返回”也存在，源码会使用现有导航历史；本包记录它的存在，不扩成另一条历史分支，不宣称所有 A 的可达路径都不可用。若出现未识别的确认／继续／恢复／重试控件，保存清单并停止待复核，不能略过后宣称整体无法恢复。
5. 保留上述 RED 后，明确记录“NEW native B review/correction”的独立边界，再对实际打开的当前 ID 重新原生校对。完整新意图单独冻结；即使 A/B 的值相同，仍是不同稿件。若将来主入口确实继续 A，也要分别证明同 ID、完整修正与原文连续，不能靠文本相似断言。

## 当前稿的精确提交前 quota

只在当前合成账号、当前页面、`quickNotes` 的 readwrite `put`，且 value.id 恰为已重新校对的当前确认稿 ID 时，同步抛出明确标注的合成 QuotaExceededError。其他库、表、ID 和 readonly 正常通过。记录实际 intendedValue 的无损表示、边界与时间、`originalCalled=false`。由 Dexie 拒绝走真实事务 abort，不手动伪造失败事件或完成事件，不替换业务函数。必须恰好一次命中、一次 native abort、零 complete；重复命中是失败。

安装后点原来的“确认保存所选记录”一次。出现失败后，在任何阅读滚动之前保存当前视野原图和错误区域的真实几何，随后才允许原生滚轮去读错误、保留稿和实际 Save。到达错误位置后可读，不等于错误自然出现在当前视野。

故障前后保存所有现存表、schema／版本、完整 settings、input/review/source/applied、完整 outbox 和从 cursor 0 到 hasMore=false 的全部 GET ledger。整个事务不得部分写入 QuickNote、Expense、Todo、回执或 outbox；非选中实体、邻居与旧稿／旧账全部保全。

错误的读者合同单列：实际错误区域能说明没有提交、修正仍保留、存储原因与真实继续操作，不能只因出现裸英文 QuotaExceededError 就算可理解。当前源码可能只显示原始异常；这要保留原生 RED，不改应用来隐藏。`重试保留修改` 是确认稿 autosave，不是业务重试；`确认保存所选记录` 才是提交业务记录。本包分别记录两个控件的可见文字与含义，不把 autosave 的成功当业务 Save。

原因、未提交和保留承诺只在实际读取的错误正文段落上判定，不能由“重试保留修改”按钮补齐；分类也须实际显示餐饮，不能只读取底层 food 值。

故障设 30 秒安全自动释放，但只有在安全到期前显式恢复原 put 方法才能继续；安全过期／原方法恢复失败不能授绿。释放后重新阅读当前修正，完整源再次相等，再点击原来的业务 Save 一次。

## 保存、原文与实际去向

成功后必须恰好增加一个当前 ID QuickNote、一条实际生成 ID 的 Expense 和一条实际生成 ID 的 Todo。exp-0/todo-0 只是 note 内的候选 ID，绝不能当持久记录 ID。只读 applied receipt 必须完整包含实际生成 ID、正确标签／日期／效果、完整指纹、当前原文、owner 与本次时间，source 保存完整当前稿；当前 review/input 只按实际消费范围移除，A 不因 B 提交被消费。

服务端只允许新增对应三条事件，完整旧 ledger 前缀必须逐值相同；每条实际 ID 有自己的精确版本 ACK、无冲突、整个 outbox 空。服务端日期、金额、收入方向、内容、默认字段及真实审计时间完整保存和校验。所有本机旧对象／未知元数据、非选中记录、邻居、A 与旧输入都必须保持原值，不能只比计数或标题。

最终从可见 receipt 链接逐个打开真正的原始速记／Timeline、Todo 编辑器、Expense 编辑器，读到对应原文、内容／日期／金额／方向，再用页面真实返回控件回到同一 receipt。编辑器只读取和取消，不引入新修改。之后从可见导航打开 Timeline，真实单击“全部记录”，等完整 URL 与唯一选中态稳定后才冻结 origin；打开实际原文、返回同一范围，再从原文的“查看本机保存结果与去向”回到同一 receipt。不得沿用切 range 前的旧 URL 制造误红。

## 保全判据与停止边界

源读取复用已经存在的 account reader：先枚举实际库，无版本 open，upgradeneeded 立即 abort，只读所有现存表。原件保留字段存在性、undefined、负零和可支持对象类型的无损表示；断言不靠 JSON 丢掉元数据。

settings 不做 capture 前缀整体豁免。每个预期 input/context/review/current-pointer 写入都列确切 key 和完整预期值；只允许 key/value 外壳，原外壳有额外元数据不能静默抹除。故障 Save 的 autosave 应保持完全同一稿，若发生未解释的元数据改变直接失败。只有普通后台 `lastPullAt`、业务 ACK 时的 `lastPushAt` 可按应用实际生成的规范 UTC ISO（带毫秒）时间非倒退推进；也完整记录差异。setup邻居也必须实际存在完整的version行且值等其唯一服务器事件seq。当前review、pointer、input/context在消费前均核完整key/value外壳；出现不明外壳即停止，不声称已为未知历史外壳提供恢复能力。只在成功的实际 ID 上增加准确 version，按完整名单消费当前稿，没有宽泛忽略 settings、游标或权限字段。

完整分页须严格匹配实际协议：protocol=2和goals-v1能力，hasMore为boolean；非空页nextCursor必须等该页末事件seq，空页保持输入cursor且hasMore=false，只在明确false时结束。不要求跨账号共用序号在本账号内整数连续，但不能任意跳cursor漏掉本账号事件。

GET 只使用页面现有同源身份自动请求 `/auth/me` 与完整分页 `/sync/pull`；不读取／重放 cookie，不写业务 API，不改 owner、会话、generation 或权限。网页原生业务请求仍由应用正常执行，完整 driver traffic/trace 随工件保存。

发现未验证源改变、机械 fault 不精确、未完成读取、意外控件或安全截止时，先保存首败原件，再只做只读保全和显式 cleanup，不继续业务动作。一个可理解性／连续性的产品 RED 可以保留后继续已声明独立诊断；源保全失败则必须停止。原生 RED 要保持 CI 非零，不能 expected-pass 或 continue-on-error。主按钮回 B 的源码判断不是已经运行的浏览器事实，未到达尾项必须写未执行。

暂停范围继续绝对生效：偏好 authority／clear-generation／publication 安全审查和其依赖的提交后读取修复都没有重建、重命名、委托或导入。没有本地 browser、监听器、替代端口／二进制／隧道、依赖安装、真实提供方或生产动作。

# 当前频率调整：独立Y5b候选

## 新合同与未完成项

本任务是“立即调整当前计划”，不冒充此前未通过的“预约未来生效并重建历次规则达成率”。当前候选提供每天/每周一次，保存前显示原频率和新频率下的当前进度，例如周二已做、周三未打卡时，从“本周已完成”变为“今天尚未记录”。没有自动补卡，也不抹去周二事实。

过去只显示原实际打卡日期和记录次数，不用新的频率回算历史完成率。改动沿用同一习惯ID、标准版本化同步和updatedAt；页面显示本机记录最近更新时间，云端审计时间另行核对。**不支持指定未来生效日期、完整历次频率规则回溯或过去目标达成率重建**，它们仍为Unsupported/未完成，综合验收需显式列出，不能因为当前CI通过而写成全量完成。

## 写入和失败合同

- 预览保存打开时的完整父行、全部打卡事实和业务日期。保存与核对在同一事务内；父行、任一事实、账号/会话/clear epoch或日期已变化则拒绝，要求重新核对
- 只改同ID的frequency和updatedAt。createdAt、未知字段、所有true/false打卡及其来源/说明完整保留，wire仍使用旧协议已支持的字段，不引入隐式历史字段
- 取消没有写入。存储不足时原计划和打卡保留、当前选中的新频率保留；释放问题后在同一编辑框中点“重试保存”
- 保存期间不可继续切换选项或关闭，防止旧快照提交后丢掉新输入。已经提交但列表刷新失败单独提示，不当作写入回滚，也不重复入队

## 支持链与旧诊断分开运行

默认CI的`habits`只验已支持的周语义、补记撤销、完整来源删除与实际失败恢复；`habits-frequency`独立验证上述即时调整合同。原`inspectFrequencyEdit`未来生效/历史断言原文保留，未改为通过：在GitHub Actions手动运行CI时打开`include_unsupported_habit_history`，将以`AUDIT_INCLUDE_UNSUPPORTED_HABIT_HISTORY=true`执行。诊断先检查实际编辑器的限制声明：明确不支持未来/历次规则时，记录红项、取消且核对无写，绝不替未来意图保存即时改动；其余条件才进入保留的原始断言，当前预计仍报告缺口。未开启时报告明确列Unsupported，不记pass。

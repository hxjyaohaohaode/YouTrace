# 习惯既有记录链：修复候选

## 状态与原始红基线

这是待原生界面和独立复核的实现候选，不能当成Y5、全部习惯功能或全产品完成。

仅测试提交 `da4c623432e620c648c41a71e16f060063666236` 的 [CI 37282197121](https://github.com/hxjyaohaohaode/YouTrace/actions/runs/37282197121) 保留139份原始习惯工件。受控周三的两种宽度中，周二打卡真实完成并同步，首页仍显示0/1；习惯页没有可读的自然周范围与本周达成语义，移动端日期控件缩成窄小圆点。频率编辑入口缺失，继续开放，不按通过记账。

桌面删除在脚本的“本机必须已有服务器updatedAt”前提处停止，并没有执行原生删除或命中quota。真实同步/重载后，本机可保留本地创建时间而服务器使用引擎创建时间；同ACK版本的pull不必重新覆盖本机来源。这一前提已更正为核对完整实际来源、独立保留两边时间，不填充或删除字段。带服务器附加字段的完整CAS另由模块测试验证。

移动端普通顺序补记还出现本机true、服务器false、outbox1停留15秒，没有相应最后POST。独立实际store/syncEngine＋Hono/Prisma＋fake-indexeddb定位到单飞同步收尾丢唤醒：新操作落在最终count之后、flushing释放之前。修复记住当代同步请求，在收尾重新安排，保留既有退避；暂停使旧代请求失效。此模块证明不能替代新原生结果。

## 当前修复合同

- 每周明确为周一至周日一次。达成本周与“今天是否做过”分开；周二事实可完成本周而周三仍未打卡，不要求重复完成
- 首页与习惯页共用当前期间算法。createdAt是审计时间，不丢弃用户明确补记的更早事实；前周/未来打卡日期不完成当前周，异常的未来审计时间也不隐藏既有习惯
- 所选图标始终保留以区分同名记录；近7天显示实际日期，日期按钮不被标题挤压。每次操作明确日期和目标true/false，不把旧页面“补记”倒转成对端已经true的false
- 完整父行和打卡来源随视图冻结，写入前捕获账号、会话代次、数据库与clear epoch，事务内核对。迟到读取不复活清除数据；缺失父行不产生孤儿打卡；wire字段使用白名单
- 创建表单持有稳定ID；同事务本地创建回执区分同次重试，避免业务已提交、随后读取失败时重复创建。返回结果明确本机提交和列表刷新是两件事，不冒充服务器ACK
- 删除使用确认时的完整父来源，包括实际存在的updatedAt及未知字段。原子删除父/子和写outbox；相关待确认outbox或冻结请求存在时保留原记录，等待同步后重试，不丢弃队列来实现离线删除
- 存储不足用中文解释并保留原数据，可按原来源重试；冲突请求刷新核对，不替换成最新来源偷偷继续
- 近7天回顾改为真实记录次数/天数，不用当前频率回算历史达成率。服务端当前期间另外给出频率、起止和具体完成日期；周习惯不输出日连续奖励，日事实连续长度不被60天查询窗口截断

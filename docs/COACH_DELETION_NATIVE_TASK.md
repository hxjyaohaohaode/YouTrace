## 指定任务

1. 桌面 profile A 通过原登录/注册和开发合成OTP登录。用原待办表单创建一条真实记录，等待实际云ACK；用原设置开关、时间分段键盘和首页规则生成一条本机晚评提醒。
2. 显式声明隔离 SQLite 历史 Push fixture：两条已有云提醒，由应用正常API加载。它代表旧服务器历史；当前没有公开创建云提醒的API，不能声称此步骤是原生生成/后台送达。
3. 创建独立 Chromium profile B（360px），用相同账号普通OTP登录；不能复用A的Cookie或IndexedDB。确认原待办与两条云提醒已实际加载，并有本机规则生成的提醒。
4. 在隔离服务源加入55条更晚的已读历史提醒，让目标/对照活记录都落在最新50条之外。缺席不表示删除。
5. A点击原“关闭推送”控件。明确的一次fetch替身先等待真实DELETE成功并读完响应，再向应用抛出传输失败。确认服务端已删且有墓碑，A仍保有原控件并显示失败；期间加入一条明确的新服务源提醒；用户再次点同一原控件，实际同ID DELETE重试，服务器仍只有一个删除事实。
6. B普通重载。必须从真实核对HTTP收到确切墓碑，原生IndexedDB和页面才删除目标；原待办、全部原本机提醒、分页外活提醒逐字段保留，新提醒完整进入。再次重载不得复活或误删。
7. B用原设置退出、另一个合成账号OTP登录、退出后原账号OTP重入。新账号不得显示或拥有旧提醒/待办；原账号数据库保留，回来仍保持原文与删除状态。

两profile保留各自录像、一个browser-global trace及target身份、逐步截图、完整只读原生IndexedDB快照、限定服务端Push/墓碑/变更流和请求账本。读回不会创建缺失库；当前业务表和outbox逐值保留断言独立于UI；原coachInsights逐条保持，允许Home新增简报；原settings仅允许规范单调lastPullAt、绑定原owner/epoch的扫描cursor与精确目标墓碑变化，其余逐值保持。新账号可有其合法本机提醒，但不能含旧账号ID、私有云提醒原文或待办。记录失败和原始来源，不用后续成功覆盖首次失败。

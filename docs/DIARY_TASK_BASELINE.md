# 普通日记：原生用户任务红基线

应用基线：`07bc198487a883fc9e508520a2eaef6d2bd1dd74`。本文件与 `youji-app/scripts/audit-diary-outcomes.mjs` 是下一轮取证合同，尚无这两条任务的新原生 CI 结果或独立媒体验收。既有 Timeline/Capture 旧日记纠错证据不自动授予完整 Diary 通过。原名称、Logo、Login、Splash、应用/服务端实现没有在本包修改。

入口为 `runDiaryOutcomes(ctx, { scenarioSet: 'records' | 'recovery' })`，返回 `{ media }`。分别交给 `diary-records` 和 `diary-recovery` 两个独立任务，每个运行 1280×900、360×800 两个全新合成账号 profile。每个昵称不超过 20 字符。沿用现有 8 分钟取证 step / 20 分钟 job 上限、实际录像/截图/DOM 只读快照/trace 及有界收尾；本地不启动 Chromium、监听器或隧道。

## 现有语义和应到达的终点

当前 server `Diary.@@unique([userId, date])` 与 `DiaryStore.assertAvailableDate` 都要求每天一篇。第二份同日输入应被明确拒绝，不能覆盖原文，也不能通过改成不真实的日期绕过。现有编辑器的“保留当前稿，打开这篇日记”是可实际操作的原记录入口。本轮不添加或假设同日多篇、合并、两设备冲突解决。

三个恢复事实分别记账：

1. 普通提交前 put/delete 配额拒绝：原记录、完整编辑稿和来源保留；显式解除同一个故障后，真正点击现有“保存”或编辑器中的“确认删除”重试
2. 编辑器删除成功后：原 ID 的 tombstone 已确认，当前完整编辑稿仍可核对；“另存为新日记”创建全新 ID，原 tombstone 和历史保留。这是当前编辑器内的显式新建副本
3. 真正撤销原记录删除：源码无此能力，`Unsupported / untested`。没有恢复旧编号、跨页找回已删除稿或后台复活的通过声明

列表“确认删除”明确不可撤销，本轮只打开后点“取消”，绝不点它的最终“删除”。实际删除仅发生在本任务已原生创建的隔离合成记录上，使用有完整保稿文案的普通编辑器。找不到实际编辑器/复制备份/另存入口时停止依赖路径，不种入状态、不拼隐藏恢复 URL。

## Records：录入、阅读、保稿、同日拒绝、准确更正与返回

实际登录/引导 → 首页原生导航（日记；360px 经“全部功能”）→ 三篇不同真实业务日期的原生录入 → 每次冻结 date/content/mood/moodScore/source 和持久草稿中的实际 ID → 保存、同 ID ACK、所有旧本机/服务端行与版本及完整全实体账本前缀保全。

三篇日期是 2026-10-07、10-06、10-05。前两篇故意同内容、不同绝对日期；长文是多段借书、浇花和散步的普通经历，包含明确末句。第三篇是低于 100 字的四个短行，末行“末行：蓝色书签”。这都是合成记录，不映射实际私人经历。

1280 用户明确点“未记录心情”，360 用户明确点“不错”，读取真实已选评分 7/10。不同用户自行选择，不强加情绪；空心情不得变成默认评分。创建后再次用最初冻结的三篇声明绑定实际 ID 校验，不能从后来已偏离的来源重新生成“正确”期望。

列表按实际绝对日期、内容首行与心情/评分定位，再用 ID 旁证；不靠隐藏 ID、数组顺序或记住 DOM 顺序选择记录。长文先记录原折叠状态，再点击真实“展开”，用原生滚轮逐个实际换行阅读并截首/末段。四短行单独记录，不因字符数少就假设能读全。

随后同日新稿输入另外一段补充，先核持久草稿与原源全保全，再分别实际阅读“本次不会覆盖”和保稿/核对/不要填假日期指导，核真实保存按钮禁用。点击真实“保留当前稿，打开这篇日记”，先核原日期/原内容/原心情，再关闭编辑器读取原列表正文；再次点“写日记”返回原第二稿，全部字段、草稿 revision/base、原记录、邻居、版本、队列和全账不变。该稿继续保留。

准确打开当天原篇，只更正 content。打开/输入前先冻结完整原源，再与输入后的来源比较，只允许该精确草稿键写入；不得把期间变坏的记录或旧账当成新基线。输入后取消，原行不改；重开全部实际字段与持久稿相同；保存后同 ID、同原日期与心情、原 createdAt、其他所有已存在字段、全部邻居/版本/历史账本保全。仅该 content、本机合法 updatedAt、服务端独立合法 updatedAt 和该次精确同步/草稿消费元数据可以改变。全文阅读、短稿打开/取消、同日第二稿最后取消及新副本阅读，也分别与进入该段之前的完整来源严格比较。

从真正导航进 Timeline，点“全部记录”，凭实际绝对日期和更正后独特首句阅读并点真正记录按钮。包含换行的 aria-label 用实际字符串匹配到唯一 DOM 节点，再经原几何和单次鼠标点击，不把 JSON 转义当 CSS 字符串。只授预览实际读到的首句与日期，全文阅读另在 Diary 记账。核当前编辑器字段和实际 URL 中的同 ID，关闭后点“← 返回时间线”；原 `range=all` 和当前内容仍在，全部来源与账本保持不变。

## Recovery：原提交前拒绝、可见重试与新 ID 副本

另起账号，原生创建当天与前一天两篇四短行记录，逐笔核最初声明。当天编辑 content 至完整四行更正文，草稿已持久化后，安装仅命中精确账号数据库、`diary` 表、读写事务及该 ID 的原生 `IDBObjectStore.put` 故障。在原方法前抛 `QuotaExceededError`，记录意图值、单调时间、合成 Date、一次命中、一次事务 abort、零 complete。所有其他 put/delete 调用走原方法。

原错误编辑器保持打开，先采真实错误、全部原源/草稿/队列/版本/全账，再显式解除，原可见“保存”直接重试，不重输、不换 ID。机械上能重试，与提示是否让普通用户理解未保存、存储原因、下一步分开；原始 `QuotaExceededError` / Synthetic 英文不授用户自助恢复通过。

保存后，从同一实际卡片打开列表删除提示，只点“取消”，核全源不变。再进普通编辑器，通过真实键盘重新输入已经读到的相同正文，确认完整日期/内容/心情/评分及 full base 都已持久化。编辑器“删除”→阅读“不能撤销为原记录/当前编辑稿会保留”→精确该 ID 的原生 `IDBObjectStore.delete` 提交前 quota 拒绝。

`DiaryEditor.remove()` 在删除事务前主动 `draft.update(form)`，故此次允许且逐项记录该精确 `record-draft:diary:<oldId>` 键的非空 revision 更新；整个 value/form/base、所有其他 envelope 字段/键和其余 settings 不可改变。这个例外不用于 put 拒绝或取消。故障必须一次命中、一次 abort、零 commit，原记录与邻居、版本、完整全账保留。

显式解除同一个 delete 故障后，实际点现有“复制完整输入”。若出现完整备份 textarea，必须对完整字节比较并用原几何实际读到标签和可达控件，即使同时出现已复制回执也不能跳过字节比较；若未出现 textarea 而真实 UI 报“已复制”，必须实际读到可见成功控件，仅记录这个 UI 回执，不声称已独立读取/粘贴验证 OS 剪贴板。随后核来源和持久稿仍完整，再在仍打开的编辑器确认区点“确认删除”真实重试。

删除 ACK 后要求原 ID 在本机和服务端均不存在、版本精确等于最后一个 delete event、空队列、保留全部旧事件/墓碑与邻居、完整编辑稿仍在。阅读“不恢复已删除编号”的说明后，点“另存为新日记”。新 ID 不得等于任何旧 Diary event 的 ID；新副本必须与实际可见输入的日期/全文/心情/评分相同，source 为 manual、本机 quickNoteIds 为 []，本机和服务端分别具有合法的新创建/更新时间。旧编辑器 draft key 被消费；旧 ID 的 tombstone、全部历史事件及其版本不变。这不声称两个记录的所有非界面元数据相同。然后通过真实卡片和 Timeline 路径再次核新 ID 与当前输入。

两 fault 均只拒绝提交前写入，不延迟提交、暂停发布或注入读取故障。30 秒安全截止和 finally 显式恢复保留；过期、未命中、多命中、意外 commit、源或输入变化均终止该 profile。解除失败单列工件/动作，不覆盖已发生的首个失败。另一宽度独立运行。

## 阅读证据与源码风险

`initialSessionGeometry` / `preparePreferencePointer` 只复用成熟几何：真实祖先裁切、绘制、底栏、中心命中、稳定帧和 hover 后语义/位置复核。普通交互没有 DOM click、value 赋值、造 change 事件或直接路由。

原 geometry 的横向 `scrollWidth` 判断不足以发现 Diary 的纵向 line-clamp。本脚本对普通正文每个非空白 glyph 建立 Range，合成实际换行框，比较自己/祖先裁切、真实前景命中、视口和底栏，逐行原生滚动后留读数。所有非空白 Unicode 码点必须计入布局与实际阅读分母；返回零 Range 框的字符也算未读，不得从分母消失。同时记录 scrollHeight/clientHeight、原 lineClamp 及末行截图。较高正文分帧读，不要求整段一次塞进视口；没有读到的内容不因 innerText 包含而通过。

源码当前风险：卡片默认 3 行，只有 `content.length > 100` 才提供展开。四短行低于 100 字可能丢失列表末行可读入口。原生前只记源码风险；若 CI 实际复现，只判列表缺口。另打开四短行的真实编辑器，核完整 value 与实际 textarea 几何、内部 scrollHeight/clientHeight/scrollTop，只有短文整体在可见 textarea 内时授这条阅读路径；不把完整 DOM value 当阅读证据，不声称资料丢失或所有路径都不可达。

## 旁证域、检查与未覆盖

GET `/diary` 与从 0 分页的完整 GET `/sync/pull` 原账本；REST 当前行必须与完整原账重建逐字段一致，Diary 删除事件的 data 必须是服务端实际规范的 null。每个关键前/拒绝/后采 `diary`、`settings`、`outbox` 三整表，并保留所有实体 events 和 Diary 子账；这是限定三表样本，不是全库备份。ACK 必须同 ID、界面业务字段一致、精确正整数版本等于最终该实体事件 seq、无 conflict、空队列。新增/更正/删除/复制各只允许准确一个 Diary event，旧全账前缀不能改变或夹带其他实体事件。

本机快照保留所有存在字段和 own-undefined，Date/BigInt/特殊数字/Map/Set 采用明确类型标记；marker 冲突、稀疏/扩展数组、未知对象类型与自定义 toJSON 对象停止采样。不宣称支持任意历史 structured-clone 值。原生不注入 unknown 字段；纯反例覆盖未知字段丢失、来源/base/envelope 变动、已存在 own key 丢失、邻居被改、版本错误、额外事件、墓碑改写与旧 ID 复活。服务端全字段和原始 createdAt/updatedAt 单独存，不为“本云相等”删掉本机 quickNoteIds 或服务端 userId/审计时间。

浏览器 Date 沿用 `createHabitAuditClock` / `installAuditDate`，以 `2026-10-07T04:00:00.000Z`（上海 10 月 7 日 12:00）为锚继续推进；计时器/performance/Cookie 保持真实，Node API 不加载 Date 替身。工件同时记驱动真实观察时间、浏览器合成时间与服务端原始审计时间，不假设三者相同。

# 旧本机目标选择与保全任务基线

本包在已验收的新账号目标任务之后，单独检查指定格式的旧账号本机资料。基线应用为 `ccba25822b92cf7de890ccf29d93679c6d794940`。新增脚本只准备真实浏览器结果合同；尚未运行的步骤不记通过，源码与模块证据不替代界面验收。

## 来源与身份

使用一次性合成服务器和原生浏览器注册取得账号。另一干净profile在登录前构造该已验证账号的历史物理数据库，再通过真实OTP界面登录。夹具的旧schema、完整原始行、未知字段与原主键全部单独记录。业务操作仍使用可见界面的鼠标、键盘和正常滚动，不注入认证或直接调用业务写接口。

两份同名目标具有可读且不同的描述、分类和进度，包含一个空字符串计划日期。未知字段是明确标注的合成内容。目标A的选择上传与目标B未选择保持分别核验；空日期随后作为独立任务，不能在初始化时改成方便上传的null。当前代码允许本机空日期、但服务器可能拒绝其上传，这个既知缺口须保留为结果，或经过用户可理解的纠正路径另行闭合。

## 必须得到的用户结果

1. 进入目标页能知道哪些资料仅在本机；未勾选时不上传。上传确认明确显示目的账号、所选同名目标的区别及实际上传字段，取消不改变原行、队列、备份或云端。
2. 选择A时一次限定的本机写入失败应保留选择和原始资料，错误与继续操作实际可读。明确解除故障后操作真实可见控件重试，只有A进入并完成同步，B和未知原文留在本机；完整云端账本及网络载荷证明没有附带未知字段。
3. 空日期旧目标的校正必须是明确、可理解的用户操作。原始空值保留在备份，不以“加入同步队列”冒充云端已接受。失败队列、输入和原始来源不能被测试脚本删除来获得通过。
4. 比较旧来源时，入口与确认画面能区分同名目标并显示当前内容、旧原稿、目的账号和copy/keep含义。取消无写；生成副本不覆盖原目标或自动上传；保留当前也保存处理记录和原稿。重复处理或重载不增加副本，删除已经生成的副本后不能由同一处理记录复活。
5. 副本或选择上传已真正提交后，再单独触发限定的列表读取失败。需实际读到已保存事实与恢复入口，释放故障后操作刷新或明确恢复控件，验证同ID、无重复、无第二次业务事件。提交前quota不能代替这个结果。
6. 从设置实际下载并打开备份，验证原始行、未知字段、当前副本和处理记录。下载成功提示本身不算文件保全证据。

上传披露须与实际白名单一致：标题、描述、类型、领域、优先级、进度、计划日期，以及目标编号、创建时间等识别和记录信息。当前正文只列部分字段而使用“仅上传”，即使逐条预览显示了分类，也须作为原生读者检查项；不可把未披露的附加字段或未知内容默认为获得许可。

## 两种旧来源不能混用

历史物理库迁移后的旧窗口继续写入，目标是保留的升级前数据库；现有行为是提示并分别导出升级时快照与旧库当前内容，不自动覆盖当前目标。此段需保持原库与当前库分离，并实际核对下载文件。

当前generation保留的`goals`来源表比较/副本，是另一个明确标注的合成来源变动夹具。它用于检查已有比较组件，不能说成旧JavaScript会写入当前generation，或宣称升级前所有后续改动已有一键恢复。

## 取证和边界

1280与360分别保留连续视频、实际PNG、Chrome trace、操作账、原始对象、队列、版本和完整GET-only云端变化账本。故障记录精确方法/事务、命中次数、硬截止和显式释放。正文与控件保留真实裁切、遮挡、中心命中与正常滚动要求；只读DOM值不替代实际可读内容。

初次发现缺口保留红证据，再修复并按新精确SHA复验。不同来源/失败任务可分开执行以避免一处失败掩盖其余结果，但没有执行的端点仍是未覆盖。匿名共享库归属、真实用户历史损坏、任意未知结构、生产迁移、完整备份导入、全无障碍和真实手机不在本包的通过范围内。

## 本地准备核对

两个CI分片分别为`legacy-goals-enrollment`与`legacy-goals-source`，现有任务继续独立运行。候选只改任务脚本、纯oracle、CI注册和必要说明，应用、服务端及数据库schema与ccba一致。前端515项、后端55项及双端lint/类型/构建通过；两个任务脚本语法检查和原品牌/入口字节检查通过。六项新增纯测试验证原键/原值、完整来源比较、未知字段外传检查及云端证据的判定逻辑，不代表原生任务已通过。

独立于浏览器的当前真实store/Hono/SQLite＋fake-indexeddb实验已观察到：空日期上传返回400，原稿备份与待处理队列保留；用户编辑器等价的空日期保存改为null后，同ID上传返回200并清空队列。它只证明存在技术修正路径。真实界面是否解释原因、让用户知道如何修正，仍由新的原生读者证据判断。

## 后续诊断与保全候选边界

初始化观察只记录固定阶段、成功/失败/超时类别、安全异常名称、布尔状态和计数；应用内存最多160条，合成浏览器跨文档最多2048条。字段先取一次值，再对白名单验证并记录，不接受验证后改变值的getter。原始错误消息、记录内容、账号编号、会话修订值、cookie、请求头和查询参数不进入新诊断。普通应用不新增诊断网络上传。

首个浏览器失败保留原截图、正文和非零退出，并保存阶段轨迹；诊断自身保存失败也不得阻断原证据。初始化的12秒截止、加载调用顺序、Promise结果、现有恢复与取消规则不改变。它用于定位问题，不能作为初始化已修复的结论；模块另发现的签出/401状态缺口也没有在此次观察代码中修复。

另有一项限定的本机编码修正：可伸缩ArrayBuffer在字节相同、容量改变时，旧编码未能区别，可能漏报旧来源变化。新增回归先观察到漏报，再验证编码保存resizable/maxByteLength，来源检测与实际导出保留这两项信息，检测/导出不覆盖当前资料。该范围已有独立模块验证，仍不意味着所有原生对象或恢复导入已支持；可伸缩视图的隐藏长度跟踪状态、部分封装原生值及任意历史格式仍不作完整无损恢复承诺。

本轮最终本地前端530项、后端55项及双端lint/类型/构建通过，原品牌/入口字节不变。独立复核包括初始化12项专项与7项额外逆向、取证8项纯合同/归档往返，以及容量编码的94项既有组合与6项额外验证。计数有重叠，不相加为产品覆盖；新精确SHA的原生行为、完整媒体和初始化根因仍须另验。

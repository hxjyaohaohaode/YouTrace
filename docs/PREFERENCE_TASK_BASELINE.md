# 账号偏好：选择、保存与恢复的原生任务基线

状态：首轮原生取证因注册响应预期和收尾问题未到达偏好任务，后续候选仍待原件，详见末节。应用基线为d54249d1d93da6bd2bddb1c73ff3e2dc38ba8b1d；本次只增加脚本、CI入口和合同，不含偏好实现修复，不更改Login、Splash、品牌资源、业务schema或服务端。

## 四组独立任务，每组1280/360

1. 正常选择与取消：通过真实导航进入设置，读账号/设备范围、应用内提醒与0为暂停的说明，操作风格、提醒开关、免打扰与晚间时间。开关即时保存，逐次记录实际ACK；之后取消未保存时间草稿不能新增写入、改时间或撤销已保存开关。重载及第二个真实OTP profile取得相同完整账号值，预算和外观仍在原设备。
2. 写入拒绝与重试：精确选择实际新时间的settings写事务，在IDB put边界注入一次有界配额故障；原本机偏好、待确认意图、outbox、恢复记录及完整云端版本保留。读取就地中文错误和原输入，明确解除故障后只点一次真实保存控件，核实完整期望值和恰好一次新增云端版本。
3. 已提交后读失败：目标写事务真实complete之后，才让settings单表readonly中读取theme的显示读失败。全表只读旁证、真实GET和ACK写事务不受此故障影响。用户必须能读到已保存事实、当前读取错误和恢复入口；解除故障后实际核对，处理同一持久意图，不能再次按Save，也不能把peer的新值当成自己的保存。最终同值、一个云端业务版本和重载保全需实际验证。
4. 两设备冲突与备份：用原生OTP建立两个同账号独立profile，由离线A和在线B的真实选择产生冲突。先完整读取两侧字段及账号身份，取消不写；两种解决方式分别用独立真实冲突。旧弹窗遇B的新版本必须重新比较，旧框仍按原快照核字段，新开框按最新快照核每个开关、0、三个时间及风格。每次选择后两profile实际重读/ACK。真实下载逐值核对双方原始快照、决定和另一个实际未确认请求。

每日上限的数值随账号同步，使用次数按设备计数。本包只测选择与保存，不把0当未设置，不授实际推送、后台提醒或全局额度执行通过。

## 证据和有界故障

每组两宽各有独立主profile、原PNG/状态、录像与浏览器trace。需要第二设备时另录其视频与target身份，由同一浏览器全局trace覆盖。当前每场景210秒，保持原CI八分钟取证上限；第一次异常后停止业务动作，保存首失败，解除声明故障并关闭profile。账号披露不足单列读者失败，允许已由真实OTP确认的合成账号继续收集其他端点；整包仍失败，不能因数据结果正确而忽略文字缺口。

注册、登录、导航和业务修改均为真实控件操作。只用GET /auth/me与/user/settings、已经存在的账号库readonly做旁证；不创建缺失库，不注入cookie、应用store或成功promise，不直接调用业务写API。每次真实PATCH立即保留请求与ACK体，核对账号、类型白名单、mutationId、基线/结果版本和期望字段。仅HTTP200、控件被禁用、下载按钮提示成功均不足以证明结果。

取消和拒绝后的保全比较覆盖账号库schema、全部表、全部settings原值及lossless表示；只有lastPullAt作为后台读取时间单独允许变化。正常提交后不要求localRevision静止，而核其单调、原epoch/version/initial、同一意图ID/body、所有非目标行和完整镜像。冲突选择按当次完整快照核所有字段，不能以两端共同错误或只改对风格替代全部值一致。

配额和读错误均由明确合成的IDB平台边界产生，按数据库名、epoch、原localRevision和实际新时间绑定，25秒自动解除只是保护期限，自动超时不能算显式恢复成功。记录命中与write-complete/read-abort顺序。所有普通原始字段整体保留；任意未知结构、历史格式与账号权限边界不属于本包的正常浏览器验收。

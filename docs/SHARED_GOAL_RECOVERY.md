## 本次能做与仍不能做

设置 → 数据透明 → 逐项恢复旧版目标。用户先备份，再预览一个只读封存快照，核对当前账号和完整原文字段，对每一份单独确认归属。事务新增新 ID 的 `syncScope: local` 副本与耐久恢复收据，保留原 ID/原文/快照、单项摘要与新 ID 映射。不会自动上传、写共享源或覆盖当前记录；相同源记录版本重试、双击、并发确认或重开预览不重复创建。后续源内容改变必须另行预览和确认，新增独立副本。

收据保存在当前账号 settings；当前账号导出包含它。清除本地数据会清除本机副本与收据并旋转 epoch，因此清除前应导出。其他账号和共享源保持独立。此功能不从旧记录缺失的 owner 字段推断归属，只接受用户对单项的明确声明，不允许直接注入伪造预览。

**自动撤销仍未实现，原需求只部分闭合。** 当前旧动态客户端能重开更高版本数据库，且 Goal 时间戳/内容相同不能证明未被编辑。因此收据固定标明 `automaticUndoProof: unavailable-unfenced-writers`，没有任何提交后恢复删除分支。比较页显示原始快照和当前副本；无论内容相同、变化、同 ID 重建或已删除，都不会自动删除、覆盖或复活。用户之后到原目标页决定普通编辑/删除是独立操作，不是自动撤销。

## 精确首版兼容范围

来源历史提交 `9abd4d3808b6d42067839333c78c482df14c9f71`：`youji-app/src/db/index.ts` 中 `version(3)`，对应 native IndexedDB 30，12 个原表、主键、自增标志和全部索引结构逐一匹配。Goal 使用字符串 `id` 主键、普通 `level/domain/priority` 索引，没有同名唯一约束。不接受任意“有 goals 表”的库；未知版本/额外表/缺表/改变索引整次预览拒绝。

逐行支持字段正好为 id、title、description、level、domain、priority、progress、targetDate、createdAt、updatedAt。字符串 ID 非空且不超过256字符，原 key 必须等于 id；文字长度按当前领域上限核验，但不裁剪空白。日期保留空字符串和 null，非空必须是真实 YYYY-MM-DD。历史时间必须原本存在、为非负安全整数，不用当前时间补造。新收据的 confirmedAt 只记录本次确认时间，不伪装历史时间。

progress 接受有限 0–100 数字原样保留，包括小数。依据是上述历史 `goalStore.ts:69–72` 的通用 `updateGoal` 可原样持久化 `25.5`；而 `:61–65` 的普通 `updateProgress` 会把它取整为26，不能声称旧普通进度控件生成小数。两条历史原代码已对合成 Dexie 真实运行核验。当前版后续普通编辑/手动进度/明确上传沿用已有验证器，可能裁剪文字或取整，恢复收据始终保留原始输入，不将这些后续操作算成本次复制。

缺失、额外、类型异常或 owner/userId 等字段不被吞掉，每行显示需要人工核对，原库保留；不选赢家、不去重同名、不转换数值旧 ID。其他实体不在本次范围。

## 一致性与失败边界

- 共享源全表单个 native readonly 事务捕获，随后复用 v2 typed graph 自验与容量限制；异步编码不延长 IDB 捕获事务。
- 预览绑定已验证 owner、物理 DB、session generation 和 local epoch；UI 对迟到结果重新核验，同步保护预览/确认/读取收据。换号、重新认证和清除后旧预览拒绝。
- source snapshot SHA-256 固定这次看的原始版本；source row SHA-256 + schema/owner/epoch 形成耐久幂等键。行摘要按明确字段顺序规范化，仅属性插入顺序改变不构成新原文版本；存储原文值不变。读取和重试均重算 row、intent 和绑定完整 snapshot/schema/key/owner/epoch/新ID/原文/确认时间的 receipt 摘要链。摘要是损坏检测，不是防止有完全本机写权限者重算所有哈希的签名。无关旧资料变化不重复复制相同行；不同原文保留为新的待确认版本。
- 副本 `.add` 和收据 `.add` 在 `goalRecords + settings` 一个事务内；不调用 outbox 或网络。空间不足/收据失败整笔回滚；提交成功后回包丢失只是不知结果，可看收据或重试，不误报回滚。
- 已确认后副本被删，重放返回原收据但不重建；同 ID 被别人重建，重放不覆盖，比较页保留当前记录。损坏收据拒绝处理，不替换它凑通过。
- 原库在快照后仍可能被旧窗口编辑。本功能明确复制封存版本，不声称跨两个 IndexedDB 实现原子“最新”读取；查看更新需要重新预览。
- 自动撤销缺乏完整写入历史。已逐项审查用户新增/编辑/进度/删除、明确上传、已知账号旧来源复制、同步 pull/冲突替换、历史迁移、native generation copy、清除，以及老动态客户端旁路。为本功能没有大改这些既有路径，没有虚构 revision 字段或 schema 版本能阻断旧写入。

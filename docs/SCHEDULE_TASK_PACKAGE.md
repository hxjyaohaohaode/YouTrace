## 当前候选实现

- 日视图显示0–24小时，同名日程按实际日期/时段区分
- 每周安排明确选择“仅这一次”或“整个系列”；单次移动/取消作为原Schedule的一份exception数组，使用同一canonical版本和事务回执；不制造脱离系列的重复实体
- 日/周/月、首页当前日程、在线回顾、有限未来聊天上下文采用例外后的发生项；时间线区分系列定义与具体单次调整，精确链接支持取消状态
- 编辑依据打开时冻结的原始记录；peer更新、删除、未知字段变化都要显式核对，不能保存时偷偷换成较新基准。取消保留本机草稿；写入失败不关闭编辑器
- 通用本地写、Todo/Expense/Diary/Schedule草稿和日程读取使用DB句柄、验证owner、会话代际/revision和clear epoch，并在最后一个await后重核；晚到身份响应不重新打开已注销账号
- 服务端新增加法迁移，不修改旧migration。单次调整进入所有Schedule变更触发器。客户端需要服务器capability且新回执明确支持该特性；旧冻结请求按原字节重放，不能改ID对应内容
- 旧客户端更改/删除带例外日程被拒绝；REST guard也在实际SQL写条件中，避免先读后写期间新例外被抹掉

## 旧JS与本机数据保全

简单升级Dexie版本无法阻止旧JS打开同库并ACK丢字段的冻结请求。因此新账号存储使用独立物理generation，按刚验证的账号复制原账号库。全部物理表、原key、未知字段/表、outbox顺序/自增高水位、冻结批次和设置保留；共享`youtrace`与guest绝不自动认领。

完整复制、校验和activation有持久记录；失败保留原库且不进入空库。clear保留cutover记录，重开不能复拷原数据。旧窗口后来修改仍在原库，设置提供状态检查和单独导出；不自动合并或上传。旧JS仍可能自己联网发送其旧队列，用户须关闭旧版窗口；服务端版本/例外门禁是另一层保护。

备份v3的`tables`是JSON阅读视图；`rawTables`才是带类型、原key和引用关系的精确保留表示。单独的generationRecovery标明升级时基线与当前旧来源。当前没有承诺一键自动恢复所有未知结构；下载、保留原库与恢复工具是不同验收项。

# 本机确认稿目录与只读查看候选

基线：公开 `484774761289f70b32c289fe616e2c736987d74b`。原需求与缺口见 `CAPTURE_RETURN_TASK_BASELINE.md:167–171`。服务基线已有只读目录；当前增量在原文页及确认页提供“查看本机未提交稿”，使用原 Modal 查看、返回目录和关闭，原编辑组件持续驻留。本轮不提供恢复继续编辑或保存所选旧稿，完整恢复需求仍为 Partial。源码/组件合同不等于原生界面已验收。

## 资格与保全

`listCaptureDraftPage` 在任何 await 前取得实际已验证的 owner、当前数据库对象、会话 revision 和内存 generation；每页读取 epoch，并在事务内及交付前再次验证。未登录、不同 owner、换号、同 owner 重新登录、epoch 变化和读取失败均拒绝，不伪装为空目录。

只扫描当前账号物理库的 `capture-review:` 主键区间；每项须 key 与原 ID 精确相等、明确具有相同 owner/dataEpoch、当前已知字段与类型、原 authenticated 会话标记。旧会话 revision 可以不同，但只供预览，绝不重绑定为当前会话。当前实现对未清除的新库采用既有 `initial` epoch 语义：只有实际 epoch 行缺席且稿中明确写着 `dataEpoch: initial` 才匹配；缺失稿件 epoch 不补造，已存在但缺 value、undefined/null/非字符串、空值/超长或扩展字段的损坏 epoch 行均拒绝；首读、事务末和交付前使用同一严格校验。它不是导入任意旧稿的兼容承诺。

任何同 ID `capture-applied:`、`capture-source:` 或 quickNotes 行存在，都阻止作为未提交稿返回，包括损坏或 undefined 的提交标记。未知归属、不同 epoch、缺字段/未知字段、坏 schema、稀疏/重复候选 ID 和超出声明范围的稿都跳过且完整保留，只给本页总 skipped 计数，不暴露被排除项的原文/ID/归属。不会调用 `loadCaptureDraft`、解析、创建稿、保存、认领、上传或写当前 input/review 指针。

返回 detached 原始字段副本，不裁剪文字、不重算日期、不改候选选项。已知未完成编辑值（例如空名称、0金额、未确认日期）可以保真列出；目录资格不是业务提交有效性。各字符串/候选数量边界明确限制当前支持范围：原文5000、日记及排除文字10000、每类候选100、ID256、金额文本512；超出者继续保留，不自动截断或修复。旧扩展字段不静默丢弃后列出。

## 有界分页与一致性

- 默认每页扫描20个候选 key，调用方只能指定1–50；另读至多1个 lookahead 判断是否还有候选。
- 不合格行也推进游标。因此前50条都不合格时可返回空 entries + 非空 nextCursor，不能将它显示为“没有任何旧稿”。不返回无法证明的目录总数。
- 游标是不含原文的内存不透明对象，绑定 owner/物理DB/session/generation/epoch；不能序列化后伪造或跨登录使用。刷新/重载从第一页重新开始，不持久写游标。
- 每页用 settings + quickNotes 单个 readonly 事务同时核稿件与提交标记。交付前额外 readonly epoch 检查。不宣称跨多页是同一个封存快照：并发新建且 key 排在已有游标前的稿需从头刷新才能看到；选择只读详情也须重新读取资格及精确版本；未来继续核对仍须另设计写权限交接，不能拿目录预览作为保存能力。
- 顺序仅是实际 IDB 主键顺序，不称最近修改/创建时间。capturedAt 是原文时间依据，不伪造更新历史。
- 有界的是 key 数/已支持返回形状；底层损坏的单个超大 IndexedDB value 仍可能在读取时占内存。本服务不声称防止浏览器 OOM，不生成截断备份。

## 本地证据与未验部分

基线红合同用真实生产 create/save 模块及 fake-indexeddb 生成 O/R/D，确认当前模块缺少只读目录能力。它是明确缺实现的合同红，不是源稿删除报告。曾尝试直接跨 owner bind 的测试准备被现有“必须 reload”保护正确拒绝；另一次 native transaction 观察器晚于 Dexie 绑定导致无事件，已按真实缓存机制修订并保留原日志。

新增18项真实服务 + fake-indexeddb 合同覆盖 O/R/D 精确原文/全表保全、边界与坏值、已提交排除、124候选/3页穿过55个不合格前缀、真实 readonly 模式、读取/事务 abort 失败、旧结果晚交付后的 epoch/重新登录拒绝、被绑定文档 owner 不匹配拒绝与另一账号独立库不变、游标伪造/范围、脱离引用、无网络及每页快照语义。邻接既有15项确认稿事务/幂等合同另跑，共33项通过。

服务基线没有 UI 验收；当前增量有下述真实 React 宿主合同，仍没有浏览器验收，没有以同一 document 强行切数据库冒充真实 A/B/A 重载，没有自动恢复任何未知旧稿。此前 fcec 初始化队列根因仍未知；本服务不改变原12秒、初始化或其他业务行为。全套门禁、独立审查、原生入口和发布状态各按后续精确回执，不由本合同自动授予。

独立审查在首版候选复现 epoch 行存在但 value 缺失/undefined 被当缺席的P2；原基线和实际红日志保留。修订只在目录服务区分行存在性，补初读7种坏值和迟到缺席→损坏5种矩阵，拒绝时全表精确保留，不修改全局actor或修复原库。


## 只读选择及界面边界

- 目录条目由私有 WeakMap 绑定完整 actor 和 detached 原始版本。`readCaptureCatalogEntry` 再用 settings + quickNotes 同一 readonly 事务核 schema、owner、epoch、三种提交标记和版本，末尾再次核严格 epoch/身份。伪造条目、调用者改条目、已提交/已变化、旧身份或损坏 epoch 不产生重绑定或写入。
- 版本比较固定对象字段顺序而不改原值；显式 undefined 与字段缺席、-0 与 0、数组顺序都不同。详情保留完整原文、原基准日期、修正后候选和勾选状态；“全部原始字段”用可辨类型文本保留这些差异，标明它不是导入/备份格式。目录摘要裁至120字，详情原文不裁剪。
- 选择先清旧详情进入核验态，仅首次核验成功后显示；原稿/提交标记/epoch 后续改变由 Dexie liveQuery 重新核验，失败清详情并要求重读目录。liveQuery 的 native async 回调明确保留 Dexie 异步作用域；首版非 async 包装在真实模块与 fake-IDB 上出现 PrematureCommitError，红日志和旧源码保留，改后同组件链通过。
- 关闭、返回目录、新页或失效递增请求代际并退订。旧 Promise 与刻意迟到的 observable 回调不能重新显示内容。每次发布和渲染同步复查 owner、物理DB、session revision/generation；实际 authStore 改变触发重渲染，正常认证流程继续由原路由处理。
- IDB liveQuery 不监控任意 JavaScript 内存变化。apiClient 的内部 generation 更新本身没有同文档事件；这里不承诺任意绕开真实认证流程的内存改写都会立即触发渲染，也不增加轮询/全局认证副作用。下次发布、渲染、选择或原认证流程必经守卫。
- 目录每页是已读快照，列表不会冒充全库实时封存结果。空且有游标继续扫描；末页无合格稿仍不代表没有其他资料。读失败显示错误与显式重试，不显示成空目录；未知/损坏/已提交稿只给排除计数，原件保留。
- 两个入口均不导航、不调用 `loadCaptureDraft`、不 remount 当前编辑、不触发原返回/保存逻辑。稳定编辑时全表逐值不变且原生 IDB 事务全部 readonly；若原页已有待保存队列，只允许原有那次精确 payload 自然完成。合同分别核 QuickNote 与 CaptureReview 每次仅1笔原队列写事务、调用数/原值/确切受影响 settings key，不整表豁免。保存提示可以合法地由 pending 变为 saved。

## 当前增量合同与尚未授证

真实服务共25项、真实 React 父组件/目录组件宿主共18项，另原界面兼容7项与语音状态17项，定向67项通过。组件宿主用实际 React 调度、生产服务、fake-indexeddb；路由、动画、Button 和 Modal 的宿主渲染明确替代。因此“Modal 关闭回调”只授证状态/数据取消，未授证真实 Esc、焦点陷阱、滚动、遮挡或360px可读性。一个迟到 observable 用例明确替代调度以故意违背退订交付，核组件自身代际门禁。

包括 O→完整原文/修正/选择→返回目录→关闭的两页零写、坏前缀分页、读取失败重试、提交/源版本/epoch变化失效、私有条目快照不可被公共对象改写、缺席/undefined/-0语义、旧请求晚交付、当前认证重渲染隐藏原内容、既有自动保存精确完成。原同文档 owner 不能跨库切换保护未绕过；跨账号真实重载、移动/桌面真实 Modal 和原控件流程仍待独立原生验收。

当前阶段不声明可继续编辑所选旧稿、不声明自动认领或全旧 schema 支持，不更改初始化超时或 fcec 未定位事实。独立审查、全套门禁、检查点与外部发布状态以对应精确回执为准。

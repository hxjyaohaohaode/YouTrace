# 花销与本机预算：原生用户任务红基线

应用基线：`48ea881908b433bdd0222a82f93a4f3417c0e5a0`。本文件及新脚本是取证合同，尚未取得新任务的原生 CI 结果或独立媒体验收。已有 Timeline/Capture 旧记录纠错证据不自动授予完整 Expense 任务通过；原名称、Logo、Login、Splash 不在本次改动范围。

本轮拆成两个独立任务入口 `expense-records` 和 `expense-budget`，各自运行 1280×900、360×800 两个全新合成账号 profile。入口导出为 `runExpenseOutcomes(ctx, { scenarioSet: 'records' | 'budget' })`，返回 `{ media }`。两个任务由现有驱动分别录制原视频、截图、DOM 只读快照与 trace；不在受限本地启动 Chromium、监听器或隧道。

新任务沿用现有20分钟job及8分钟取证step上限。仅新Expense任务采用与偏好取证相同的30秒CDP命令上限，并记录最终截图、录屏、trace与profile关闭的实际开始/结束/失败；不会把取证失败改成通过，也不延长业务等待或重复已经尝试的点击。

## 读者应能完成的结果

1. 从实际首页导航进入花销，手动录入带分的支出和收入。读到今日、本自然周、本月的实际支出；收入不偷偷减掉支出，也不加进“已花”。每个统计的期间标签、人民币符号、完整分金额要在同一实际卡片中可读。已有本月收入显示准确；本包不要求新增日/周收入汇总功能。
2. 两笔同名、同金额、不同绝对日期和分类的记录能凭可见内容辨认；点开的表单名称/备注、金额、方向、日期、分类与所选行一致。只把所选当天金额从 12.34 改为 9.87，取消保稿不更改原行，重开保留全部输入；真实保存后同 ID、云端版本、其余原字段和邻居保持准确，现有统计重新计算。
3. 未来日期记录仍在全部记录中可见、保留原 ID；它是否计入“已花”与记录是否存在分开判断。旧月份记录用于边界辨识，本包不是旧记录恢复或跨月筛选任务。
4. 未设置预算与明确设置为 0 可读且含义不同；有支出时 0 元不冒充未设置。正常预算及超额都保留精确分金额。预算只在本设备持久化，不声称账号同步；只有一台设备的重载结果，不推导跨设备隔离已验。
5. 真实普通写入被限定 quota 拒绝后，原行/预算、完整输入、版本、队列、原账本不变，界面说明未保存、存储原因与可用的下一步。显式解除同一个故障后，实际点击可见保存控件完成恢复；可机械重试与错误提示能让读者自行恢复分别记账。

## 两条原生路径及故障边界

### Records

实际登录/引导 → 首页花销导航 → 七笔逐次创建、同 ID ACK、所有旧本机/云端行和版本不变、完整全实体账本原前缀不变且只新增该次一个 Expense 事件 → 按最初声明的七笔输入逐项绑定实际 ID 并再次核全部字段 → 实际阅读同名日期和未来行 → 展开统计、核对期间/币种/分数与同日列表净额含义 → 打开准确当天行 → 输入 9.87 → 取消保留草稿 → 原源及全部支出读数仍准确 → 重开相同完整输入 → 保存 → 一个准确 Expense 更新事件、同 ID 云端确认和邻居不变 → 重新阅读统计、打开核对已保存金额 → 首页返回花销并继续读相同结果。

### Budget

实际登录/引导 → 首页花销导航 → 未设置预算 → 保存明确 0 → 三笔原生收支 → 带支出的 0 文案 → 10.01 预算/4.34 超额 → 输入 12.02 后取消保留本页输入 → 重新打开 → 限定预算 put quota → 原内联错误、完整输入及 10.01/配置标记不变 → 显式解除 → 原内联“保存预算”直接重试，不重新挂载、不重输 → 12.02/2.33 精确结果。

随后从可见同名当天行进入普通 Expense 更正，输入 13.57，并对该精确 ID 的 `expenses.put` 做第二个独立故障：

- 1280：错误编辑器保持打开 → 原完整来源/草稿旁证 → 显式解除 → 原“保存”直接重试。遮挡的背景统计不被称为已读
- 360：错误编辑器保稿 → 显式解除 → 真实“取消（保留草稿）” → 实际读到未改支出统计 → 重开同一可见行、核对完整保留输入 → 原“保存”重试

每宽只授予真正操作的恢复路径；不能把窄屏取消重开的结果称为“原错误区直接重试”。两宽预算都保留内联表单直接重试。重新打开结果、统计重算、正常重载后同设备预算和同 ID 记录仍准确，分别留证。

两个 fault 都是提交前拒绝，不延迟提交、不暂停发布、不注入读取失败：

- 仅包装原生 `IDBObjectStore.put`，匹配精确账号库 `youtrace:user:<owner>:schedule-v1`、读写事务、表与主键
- 预算只匹配 `settings` 的 `monthBudget` 行；记录只匹配 `expenses` 的选定 ID。其他调用直接调用原方法
- 匹配时在调用原 put 前抛出 `QuotaExceededError`；记录命中值、事务 abort/complete、单调时间、合成 Date。必须恰好一次命中、一次 abort、零 commit；这不是提交后读取恢复
- 30 秒安全截止且显式 finally 恢复。安全截止触发、fault 未命中、错误事务提交、源变化或输入丢失都使该 profile 停止业务动作；不重置来源、不删字段、不以新建替代原 ID
- 在输入草稿已经完成正常持久化后取 before。Expense draft 真正的键为 `record-draft:expense:<id>`；它与原 Expense/版本/冲突/outbox/Expense 账本一起精确对照。取消和故障不得悄悄改这份基线，合法记录保存消耗该 draft 的事实独立保留。所有 settings 行都比较；非业务写入只允许明确记录且合法单调推进的 lastPullAt 观察时间，预算成功只额外允许所选预算两行，Expense 成功只额外允许精确目标版本、该 draft 消耗与 lastPushAt。正常重载另单独允许 syncV2Cursor 从合法原值单调推进至已完整观察且未改变的账本末尾；不全局排除 cursor，所有实际 settings 差异在关键断言工件逐项列出

## 证据与判定

每次前/失败/后旁证完整采样的是 `expenses`、`settings`、`outbox` 三张表，不是全库备份。保留这些行所有当前存在的字段及 own-undefined 标记，Date/特殊数字/BigInt/Map/Set 具类型标记；不支持的对象、自定义 toJSON 类型、与证据保留标记冲突的源对象及稀疏/扩展数组使采样失败，不宣称支持任意历史结构。此轮原生不直接注入未知字段来制造用户行为；纯 oracle 另测 unknown/缺少 own key 的反例。

HTTP 只用 GET `/expenses` 与从 0 分页的完整 `/sync/pull` 原账本。服务器当前行与账本重建结果逐字段相同；保留原始全事件及 Expense 子事件、tombstone、原版本及全部 outbox，不只留筛选后的金额。已 ACK 需同 ID 本机/云端字段、精确正整数版本等于最终 Expense 事件 seq、无冲突且空队列。正常更正只许目标 amount 改变；服务端自身 updatedAt 独立允许推进，createdAt 和其余已存在字段不得改变。邻居本机/云端完整行与版本、所有实体完整账本的旧事件前缀均须不变，只新增准确一个目标 Expense 更新事件；保全路径要求已采样 allEvents 全账本完全不变，不能只比较 Expense 子账。

所有正常输入只用真实鼠标、键盘、原生 select/date 控件。可见名字、绝对日期、收入方向/金额先定位，ID 只在其后用于旁证。几何复用已审 `initialSessionGeometry` 与 `preparePreferencePointer`：真实祖先裁切/绘制、底栏、中心命中、稳定帧、hover 后语义及位置再次核对；没有 DOM click、值赋值或造 change 事件。

`observe(false)` 保留非阻断的文案/统计/可读性缺口，允许继续独立机械尾项，但不改绿。机械前提、来源或故障证据失败则立即停止该 profile 后续业务动作，优先截首败并做只读旁证，finally 卸载故障；现有 isolated 驱动负责关闭录屏、trace 和 profile。另一个宽度独立启动。

## 2026-10-06 独立审查后的 oracle 修正

发布前审查以纯数据反例发现并关闭三个测试判定漏洞，不是新原生产品结果：

- 原 create 只核新增行 ACK 与数量；添加上月记录时，旧周外支出 321 → 999 且另补一条合法事件/版本，旧判定和服务端/账本自洽检查仍能通过。新 create 同时要求所有旧本机/服务端完整行、版本和完整账本前缀不变，且只能有一个该目标新增事件；原七笔输入与实际 ID 再逐项绑定，禁止从已偏离原输入的来源自行算出“正确”期望
- 原每日合计只要出现净额字样即可通过，或只在同一区域找到两个数字便声称总收入/支出正确。新判定将相邻标签、币种、两位分金额和正负方向作为一个事实，覆盖错误净值、缺单位、反符号、总收支互换和矛盾净额的反例
- 原保全只比较 Expense 子账，未使用已保存的 allEvents 全账。新保全要求全账不变；创建/纠正都要求完整全账原前缀不变、子账与全账一致且只新增目标 Expense 一条事件，无关实体追加或历史变更不再被接受

17 项纯正反例包含独立审查原 321→999 见证的完整重放。新脚本语法、17/17 oracle、该测试 lint、前端 typecheck 与 diff 检查已实际通过。未运行浏览器，不授予原生任务通过或发布结论。

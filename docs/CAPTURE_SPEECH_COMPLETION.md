# 录音停止后的末句与确认稿

## 用户任务与证据边界

本任务从已支持的「随手记 → 语音输入 → 查看确认稿」出发。浏览器可能在 `stop()` 之后继续交付已采集音频的最终结果；用户应能在确认稿看到这段末句。本文只涉及当前组件中的输入与录音收尾，不改变确认稿的资格、身份、持久协议或业务提交，也不增加语音提供方。

应用基线为 `af6c353fad0b476d7bf11b6d0deaf80be0157224`，`youji-app/src/pages/QuickNote.tsx` 内容 SHA-256 为 `4c582150d0de12b1394ec4302429510dda908ce845f0b735c10f9e0d5204708a`。[Web Speech API 草案的 stop 定义](https://webaudio.github.io/web-speech-api/#dom-speechrecognition-stop)允许停止采集后尝试返回既有音频的结果；它不保证具体设备的识别质量或完成时间。

下述有限重放使用真实组件源码及其 JSX 回调，明确替换 React 调度、SpeechRecognition、路由和持久层。它证明传入值和当前组件状态，不代表真实浏览器语音服务、麦克风权限、ASR、实际存储事务、账号切换或所有设备。未请求麦克风，未运行付费或外部语音识别。

## af6c 的有限失败证据

已冻结并由独立副本原样复放的主序列：

1. 当前原文 A 为「合成既有原文A：明天交报销单。」
2. 通过组件的实际语音按钮启动替身 recognition，再点实际「查看确认稿」回调
3. 组件先置 busy、调用 stop，再开始保存当次 render 中的 A
4. 在后续独立任务中，同一 recognition 返回合法 final B「合成语音尾句B：午饭15元。」和 end
5. 实际 onresult 调用 change，但 busy 使其直接返回。显示原文仍为 A，createCaptureDraft 的实际实参也仍为 A

两个红断言分别检查原文和建稿实参，都是同一个末句遗漏的后果。最终冻结结果为 10 个场景、22 条断言：20 通过、2 红，另有 1 项边界观察，对照无失败。正常 final 先到、独立停止后收到 final、无 final 的 end/error、重复查看和新输入 C 的对照均保留原结果。

cleanup 后保留的旧回调请求过一次旧源保存替身，只记录观察；新输入 C 未被覆盖，没有证明真实浏览器取消归属、实际持久写入或串稿。最初 23 条断言/3 红的输出也保留，不用最终分类抹去原记录。

原失败见证包含「等待旧实现进入保存闸后再交付 final」的内部顺序。后继比较另以实际 stop 已发生作为交付 final/end 的外部起点，分别运行原源码与候选；不能强迫正确实现仍在收尾前保存，也不能改变 A+B 的内容要求来获得通过。

## 单组件候选

生产改动仅在 `QuickNote.tsx`。每次开始使用新的 recognition 实例，回调须仍属于当前组件的当前录音；自然 end 解绑回调并清理定时器。普通停止会显示「正在接收语音尾句…」，继续接收同会话 final。查看确认稿先锁定重复提交，等待收尾后才从 latest 冻结原文和基准日期，沿原保存和确认稿复用路径继续。

收尾上限为 2000ms。error、stop 异常或到期没有 end 会保留已经显示的文字、提示核对补全，并停止本次自动建稿；用户再次明确点击查看才继续。end 没有 final 时只保留已有文字，不捏造末句。手动改字、切换文本或返回取消本组件的旧录音回调，保留用户当前输入；等待提交时模式和录音控件禁用。cleanup 只使本组件后续回调/导航失效，不撤回已发出的持久请求，也不宣称改变持久资格或账号隔离。

正式实际组件替身回归包括末句晚到、先到、独立停止、查看加入既有收尾、无 final 的 end/error、超时、重复查看、手动新输入、切换/返回/cleanup 的迟到回调、原文及确认稿保存等待、start/stop 异常和 interim。原见证不修改；继任序列确以实际 stop 为起点，在原组件上仍红、候选上 A+B 且一次建稿/保存/导航。它不要求候选沿旧实现的「先保存再收尾」内部顺序。

## 复用原两宽速记链的最短尾项

新增 `audit-capture-speech.mjs` 接在原 `capture-return` 的未提交 D 端点之后。原 O/R/D、保存拒绝/重试及回访动作和断言保留；仍使用同一 1280×900 / 360×800 profile、8 分钟任务和 20 分钟 job。af6c 该步骤实际用时 291 秒仅作预算依据，不保证后继运行时长。

1. 点击 D 的真实顶部返回，创建原应用的 composer 输入副本，完整保留 D/O/R、已提交记录、回执与账本
2. 实际输入 A「明天交报销单；」，读取原文与已保留状态。安装仅属于本页面的明确 SpeechRecognition 替身，点击原「语音输入」「开始语音输入」；此时必须还没有 final
3. 点击原「查看确认稿」。替身仅在该实例的真实 stop 调用后，用下一任务交付 final B「午饭15元；合成语音尾句」和 end。保存构造/start/stop/回调的实例、顺序和单调时间；额外 stop、错误实例、提前或重复结果均不通过
4. 新确认稿必须完整等于独立字面声明：A+B 原文、原 D 的 2026-10-06 / Asia/Shanghai 基准、当日午饭 15 元支出、2026-10-07 交报销单、当日日记尾句及原选择。不从观察到的错误稿反算期望
5. 实际读原文披露、金额/方向/类别/日期、待办与日记、选择和保存范围；不点击业务「确认保存所选记录」
6. finally 恢复两个语音构造器的完整原属性描述符或原缺席状态，保存原事件及剩余定时器诊断。全部阅读和恢复后才采终源，核当前 input/review 指针、唯一新未提交稿，以及其余原来源完整保全

只允许精确 composer 副本及其原文、一个新 review 和 current review 值的声明变化，沿原合同保留规范递增 `lastPullAt` 差额；完整原表、settings、旧稿、实际业务记录、outbox 和合并 GET ledger 不得出现其它变化。数据旁证复用原只读采样，不新增身份或数据库机制。字段可读与存储逐值相符各自留证，原有失败不被后续成功覆盖。

浏览器替身不采集音频、不调用真实识别、不会请求麦克风；只验证现有页面和持久实现对这条合成事件序列的反应。error/timeout/取消等此时仅有组件替身证据，未扩大为浏览器故障矩阵；真实 ASR、权限、设备兼容性和生产仍需各自证据。

# 昨日习惯回顾：保留打卡事实

2026-10-06，应用基线 `c3d5ab1a199fc15d510bcd534c07a8e2f621f910`。这是普通首页读者含义的取证准备，当前没有新的原生通过声明。原习惯/即时频率任务见 [HABIT_TASK_PACKAGE.md](HABIT_TASK_PACKAGE.md) 与 [HABIT_CURRENT_FREQUENCY_PACKAGE.md](HABIT_CURRENT_FREQUENCY_PACKAGE.md)，其既有结果保留各自范围。

## 可证明的事实

当前只保存当前 daily/weekly 频率和日期化打卡，没有完整、可靠的历史频率生效区间。同步历史或 updatedAt 不能自动补成过去目标规则；今天新增或修改计划，也不能改变昨日应完成目标数的推断。现有首页简报却显示“习惯完成 done/total”，其中 total 是当前全部习惯数，不能作为昨日分母。

server 的 done 实际按 reviewDate 内 done=true 的记录统计不同父习惯，本机目前按 habitId 去重，尚未过滤缺父行；产品候选只补汇总筛选，不修补或删除原记录。诚实的显示合同是“该日记为已打卡的习惯 X 项”，依据当前仍保留、关联现有父习惯的该日 true 事实。false 撤销行及缺父行原字节均保留，只有计数排除它们；相同 habitId 不重复计数。这个单位为不同习惯，活动次数、点击次数和曾经提交次数没有由此得到证明；删除后的完整历史也不在当前保留记录中。createdAt 是审计时间，不能据它排除用户明确补记的更早日期。

不必为这个显示修正新增历史频率模型或迁移。旧 done/total 协议字段可以保留兼容，但新界面不赋予 total 历史目标分母含义。当前周达成仍按已实现的周一至周日规则显示，昨日 0 项保留打卡事实可以与本周 2/2 达成同时成立。加载或未知数值不能冒充明确的 0。

阅读前后保留原习惯、所有 true/false 日期事实、相关版本/outbox 和完整账；两个周一与原周二的 ID/日期/状态逐项绑定，期间明确没有打卡写入。Home 自身的规则派生材料不冒充全数据库不变；未知来源或请求归属、完整账不明时停止依赖动作。复用既有严格几何、自然滚动、真实点击及原 8 分钟操作/20 分钟作业，不禁动画、不扩期限，不新增通用录制框架。

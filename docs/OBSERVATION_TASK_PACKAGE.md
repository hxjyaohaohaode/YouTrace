## 当前实施范围

- 当前支出对比由同一个只读事务读取两个绝对日期期间的实际字段、正整型金额分、合法同步版本、待发队列和冲突。逐条列出状态与原记录入口；明确本机已加载范围，包含尚未同步的修改。
- 显示两段金额到分、笔数、收入排除与取整百分比。前段没有支出不除以零；稀疏记录只称“已记录支出变化”，不据涨幅称消费异常或行为改善。旧category=income即使isIncome=false也排除，Home口径一致。
- 查看依据直接打开那条Expense原记录，现有CAS编辑、草稿保留及同步机制不改为旁路。返回保留当前owner、本标签页的阅读位置/展开状态/来源ID；优先焦点回来源按钮。来源移出期间时解释并回标题。只存位置/编号，不缓存正文为导航状态。
- 当前记录按实际内容或合法seq、队列/冲突变化重新核对，不依赖updatedAt。显示核对时点；日期每30秒和窗口聚焦时检查。此机制尚不等于跨午夜UI已经验收。
- 历史Insight原文原样保留，默认折叠，与当前核对分开。新生成的金额保留两位小数；不回写旧快照伪造精度。历史云端反馈不清掉。
- 隐藏/恢复明确“此设备、本期间”。账号库setting只留version/revision/hidden三个叶子；不存在账号级同步承诺。同规则同期间的已知旧本机忽略可继承，显式恢复不改原历史。源记录变更不撤销用户选择。
- Home写入前在同一事务重核隐藏与actor，双标签从旧内存生成同期间同标题时先查实际库。提醒投递在预算事务内再次重核，并在所有提醒/计数写之后核验actor与期间；传递真实Insight ID。
- 可选速记按动作语义打开实际确认/保存流程，不按数据来源类别猜去向。只读核对不需要虚设采纳仪式。旧意向仍保留，继续入口不再因意向已记录而消失。
- Coach按实际可用高度布局，给底栏突出按钮及安全区留空间；空页不滚到底。欢迎只描述已加载的记录覆盖，订阅变化，不把旧记录日期当相处时间。
- 读取失败撤下当前金额/云确认，旧历史可读并可重读；选择存储失败说明未保存和恢复办法。诊断仍是设备内存中的固定事件/区域，不采集记录内容或新增遥测。

## 核心独立逆向修复

单元层使用fake-indexeddb，不能称真实浏览器IndexedDB验收。独立脚本曾发现并复验关闭四类反例：

1. 最后一次epoch读取期间登出：改为await完成后再同步核验verified owner/session/epoch
2. Home把旧收入分类计为支出：统一排除收入标志或income类别
3. Home读取选择后暂停，另一标签隐藏，再放行仍重建：选择核对与本机Insight写入同事务，投递时再核
4. 内层检查后外层写提醒计数时登出：在最外层全部写后执行末验，提醒/计数/内存共同回滚

提醒反例必须先通过正常偏好load/sync建立verifiedEpoch，断言提醒确已启用及最终写入hook实际命中。只写一个偏好fixture可能被安全门禁禁用，返回false不能证明已经投递；现已用正确前提下无末验的提交对照与带末验的回滚验证。
